# Architecture Spine Review — Rubric Walker

## Verdict

**Needs revision before independent feature builders can safely diverge.** The spine establishes useful boundaries for server-side AI, RLS, ownership, and the core stack, and it maps every FR. However, several mapped capabilities are only named rather than governed by build-stable invariants; deployment/operations is explicitly deferred, and the signup rule conflicts with the PRD’s public signup flow.

## Findings

1. **High — Deployment and operations are not yet a build substrate.** `ARCHITECTURE-SPINE.md:74–78, 86–94, 185–191` leaves the production runtime undecided and specifies no delivery/operation contract beyond server-side environment secrets and versioned migrations. Builders still lack shared rules for environment promotion, migration rollout, scheduled retention cleanup, backup/recovery, health/observability, and provider/runtime failure limits. This also leaves the PRD’s measurable latency/error targets (`prd.md:178`) without an operational target. **Close before parallel implementation:** choose the runtime and state minimum deployment, migration, secret, monitoring, recovery, and scheduled-job expectations; otherwise independently built features may deploy or fail differently.

2. **High — The authentication invariant blocks the unauthenticated signup path and omits bootstrap ownership.** `ARCHITECTURE-SPINE.md:48` says Server Actions and Route Handlers authenticate the session before invoking server modules, but the PRD requires visitors to create accounts and then join the shared workspace as members (`prd.md:61, 71`). `AD-3` forbids signup from setting the role (`ARCHITECTURE-SPINE.md:60`) but never assigns responsibility for creating the profile/workspace membership or provisioning the initial responsible account. **Clarify:** distinguish public auth endpoints from authenticated operations and define trusted profile/workspace provisioning and initial-responsible bootstrap.

3. **High — Indexing lifecycle language is insufficient to prevent divergent update/retry behavior.** `ARCHITECTURE-SPINE.md:66, 72` says old passages are invalidated before the new index is published, but does not define persisted `processing/ready/error` transitions, atomic publication, or behavior under concurrent edits, partial embedding/storage failure, and retry. The PRD requires old vectors excluded during updates, failed resources unavailable to semantic search, and retry (`prd.md:115`); the UX also names those states (`EXPERIENCE.md:90`). Without a shared lifecycle invariant, one builder could expose stale/partial chunks or mark a failed resource searchable.

4. **Medium — FR-6 and FR-8 are mapped but their distinguishing contracts are not carried through.** The map ties both FR-5 and FR-6 to `resource_chunks`/pgvector (`ARCHITECTURE-SPINE.md:72, 153, 180`), while FR-6 explicitly requires lexical matching in title/content as well as semantic matching (`prd.md:127`). Also, the spine says `searches` stores the query (`ARCHITECTURE-SPINE.md:143`), while the PRD requires each search to retain its results and, when reopened, show results against currently available resources (`prd.md:151–152`). **Specify** the lexical search mechanism and the history/reopen contract (stored snapshot versus re-query); otherwise implementations can disagree on whether keyword search exists and what a saved search means.

5. **Medium — RAG source provenance and historical source behavior are under-specified.** `ARCHITECTURE-SPINE.md:72, 131–143` says to display corresponding sources and models messages as conversation children, but does not establish a durable message-to-passage/source reference or the citation rule for each factual claim. The PRD requires every factual assertion to be source-linked (`prd.md:137–139`), and the UX requires a saved answer to remain visible when an old source is no longer openable (`EXPERIENCE.md:100`). **Add an invariant** for persisted source references, claim/source correspondence, and rendering an unavailable historical source without implying it is still accessible.

## Source consistency

The explicit conflict found is the AD-1 session-authentication wording versus public signup. Other UX/PRD expectations cited above are primarily omissions or underspecified contracts rather than direct rule contradictions. The role/property rules and single-workspace model otherwise align with the cited PRD and UX.
